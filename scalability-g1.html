Batch scaling and G1 reference collection

20 October 2026 · RTX 5090 · measured implementation, followed by a proposed dataset.

Conclusion: the full learned simulation is 5.0× faster than MPM for one environment, reaches similar latency at eight environments, and is slower at 16 and 32 environments. Transolver is batched, but feature generation, force estimation and rigid integration still dispatch separately for each environment. The current implementation does not yet provide the batch-throughput advantage needed for large-scale robot training.

Measurement scope and limitations

  • 20 warm-up intervals, then 60 measured intervals; one process per backend and batch size. GPU completion is synchronized per sample. Rendering, HDF5 recording, compilation and initialization are excluded.
  • Transolver uses unchanged checkpoint weights and BF16 inference. Neural, contact and rigid stages use separate CUDA graphs; feature construction remains eager. MPM uses outer graph capture.
  • Visible initial particle/body positions and velocities match. MPM internal stress/deformation history starts reset. Gravity and initial velocity drive the shovel; no external drag is applied. The two implementations subsequently evolve different states.
  • This is not an equal-accuracy benchmark. Final finite-state checks passed for every case; learned contact solves also passed convergence checks. These short runs do not establish rollout accuracy.
  • Memory snapshots in the raw results are device-wide usage, including runtime caches and other applications; they are not matched process peak-memory measurements.

2. G1 reference simulation and recorder

The native MPM–MJWarp task runs a pretrained G1 policy through its actuators. The robot starts on the sand, with no prescribed body trajectory. This five-second example commands forward motion, then adds lateral motion and turning at 2.5 s.

Watch the reference simulation

cd ~/isaac/IsaacLab
export PYTHONPATH="$HOME/isaac/particle_nerd/worktrees/IsaacLab-scalability/examples${PYTHONPATH:+:$PYTHONPATH}"
uv run --no-sync python -m particle_nerd.data_collection.g1_reference \
  --duration 5 --mode policy --command 0.15 0 0 \
  --command-end 0.1 0.05 0.25 --switch-time 2.5

Record two environments

uv run --no-sync python -m particle_nerd.data_collection.g1_reference \
  --headless --num-envs 2 --duration 5 --mode policy \
  --command 0.15 0 0 --command-end 0.1 0.05 0.25 --switch-time 2.5 \
  --output /tmp/g1-policy-reference.hdf5

Two-environment recording was tested for 0.2 s with perturbed policy actions. A single-environment policy recording completed five seconds. Larger G1 batches are not yet validated. The same command schedule is currently applied to each environment in a batch; initial states differ. Native termination stops the pilot batch and invalidates reset transitions.

3. How much G1 data?

Proposed first full budget: 5,000 trajectories × 5 seconds at 50 Hz. This gives 1.25 million transitions and 6.94 aggregate hours of simulation. Adjacent frames are correlated, so trajectory coverage matters more than the frame count alone.

First full dataset5,0003.57 TB4,000 training + 500 validation + 500 test

Storage is extrapolated from the measured 714,830,317-byte file, including FP32 positions and velocities, body/joint states and LZF compression. Particle payload alone is 118,440 × 251 frames × 6 values × 4 bytes = 713.5 MB per trajectory. Native last-substep foot forces are recorded for inspection; interval-force supervision requires accumulating substep impulses first.

Motion coverage

  • 70% policy locomotion: vary forward/lateral speed, turning rate, command-switch timing, reversals and initial conditions.
  • 15% policy with action perturbations: sustained, changing joint-action disturbances and recovery.
  • 10% policy standing: zero velocity command while the policy balances, including settled sand.
  • 5% zero/random-action diagnostics: nominal joint targets or bounded random targets; track falls and incomplete episodes separately.

Zero action is not zero actuator torque. Zero velocity command to a policy is also different from zero joint action. The pilot includes initial settling; production data should also sample five-second windows after settling so every trajectory does not begin with the same transient.

Decide dataset size from measured learning curves

Train with 500, 1,000, 2,000 and 4,000 training trajectories while keeping validation/test episodes fixed. Split complete episode seeds and command schedules. Measure particle-motion error, drift of stationary particles, foot penetration and coupled robot stability. Reserve unseen sand internal-friction values and command combinations for additional generalization tests; keep sand–robot contact friction explicitly separate.

Five thousand trajectories is a proposed budget, not evidence of sufficiency. These G1 foot contacts do not replace box stamping, bulldozing or shovel scooping/transport/separation data. The G1 recorder is not yet wired into the existing single-intruder training loader or an articulated learned runner. No large collection or GeoTransolver training has started in this experiment.
