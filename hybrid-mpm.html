Can a few MPM sweeps provide a useful initial solution?

Status: running. 9/12 runs completed on horde_5080 (RTX 5080). Current run: sphere-push-5. These measurements contain no neural correction or analytical force estimator yet.

Question and method

The proposed hybrid step is: a small MPM solve → learned correction of particle motion → contact-force estimation. This first experiment measures the runtime saved and the errors the learned correction would have to remove.

Each run advances a freely dynamic body and sand for 3 seconds. Initial states, random seeds and applied force/torque pulses match across budgets. Every time step performs exactly 1, 2, 5, 10, 25 or 50 contact/material solver sweeps. Newton still performs grid construction, collider rasterization, matrix assembly, history handling and particle/material updates.

Measured conclusions

  • box-lift: two sweeps take 18.46 ms versus 27.83 ms for 50 (1.51× speedup). The remaining budget is 9.37 ms before matching the 50-sweep runtime, or 4.52 ms before matching 25 sweeps. Particle position RMS error is 9.13 mm and body-force vector RMSE is 40.15 N, both relative to the 50-sweep rollout.
  • Reference check for box-lift: 25 versus 50 sweeps differ by 1.78 mm particle RMS and 6.22 N body-force vector RMSE. At 50 sweeps, 1.3% of steps meet both solver residual thresholds. Fifty sweeps are a comparison reference, not a converged ground-truth claim.

Any network and additional force-estimation work must fit inside the saved runtime to provide a net speedup. The budgets here do not establish that a network can achieve the required accuracy.

Scene conditions

  • Box: 0.12 × 0.12 × 0.08 m, 1.5 kg; 4,000 particles in a 0.32 × 0.32 × 0.16 m sand bed. An upward force pulse lifts and releases the box.
  • Sphere: diameter 0.12 m, 1.5 kg; 2,304 particles in a 0.48 × 0.32 × 0.12 m sand bed. Force and torque pulses act during motion.
  • MPM grid spacing: 0.02 m. Timestep: 5 ms. Material density: 1,200 kg/m³; Young’s modulus: 1 MPa; friction: 0.4. Initial particle positions have uniform jitter up to 20% of particle spacing.
  • The rigid ground and four retaining walls remain fixed. Body poses and velocities are never prescribed during rollout.

Timing and reference limitations

One complete warmup trajectory precedes three timed trajectories. Timings synchronize the GPU around the complete MJWarp–MPM coupled solver step. External-load staging, scene cache updates, rendering, recording, resets and compilation are excluded. Component measurements use a separate trajectory with extra synchronization and must not be added to the total.

CUDA graph capture is disabled. All physics kernels run on the GPU; Python dispatches them. Newton’s stock iteration loop uses batches, so this experiment replaces only that loop with an exact fixed-count loop and disables early termination. This is not a benchmark of the unmodified max_iterations setting. The automatic solver resolves to Gauss–Seidel; its usual warm-start and initialization operations remain.

Fifty sweeps are a numerical reference. The 25-to-50 comparison and solver residuals assess its limitations. RTX 5080 measurements must not be treated as controlled comparisons with earlier RTX 5090 measurements.

Next experiment

  1. Create low-iteration and reference solutions from the same complete MPM state, including material history. Autonomous rollout differences above are not suitable training labels.
  2. Train a small correction using particle/grid motion, material state and contact geometry. Apply the correction before the final particle/material update, or update those states consistently.
  3. Evaluate the analytical force estimator using corrected motion. If using MPM contact impulses as an initial estimate, map the contact representation explicitly and apply each impulse only once.
  4. Measure corrected rollout error and the full hybrid step time on held-out materials, object shapes and externally applied loads.
